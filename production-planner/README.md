# Планёр — облачная версия (этап 1)

Адрес приложения: https://czbjcp2yqw-dot.github.io/svoyaki-control/production-planner/

Это отдельное приложение внутри репозитория svoyaki-control. Файлы «Свояков» не изменены.

## Функции

- Регистрация и вход по электронной почте и паролю через Supabase Auth.
- Одноразовая активация владельца, заявки на доступ и одобрение новых сотрудников.
- Роли: администратор, координатор и оператор. Роли проверяются на сервере.
- Общий календарь и карточки съёмок; оператор видит только назначенные ему задачи.
- Контроль статусов, завершения съёмки и HTTPS-ссылок на материалы.
- Автообновление через Realtime и периодическая синхронизация.
- Защита от конфликтов изменений через ревизию общего плана.
- Ручной перенос старых данных локальной версии администратором.

## Инфраструктура

GitHub Pages: интерфейс в папке production-planner.

База и Auth: Supabase проект svoyaki-production (vspytqnxxpvegwohgeag).
В нем используются отдельные таблицы planner_v1_members, planner_v1_state, planner_v1_bootstrap, planner_v1_events.
Это логическая изоляция: база физически находится в том же Supabase проекте, что и «Свояки». Данные «Свояков» не изменялись.

Серверная функция: planner-v1 (исходный код backend/planner-v1-edge.ts).
Доступ к общему плану и изменению ролей недоступен напрямую из браузера. Секретные ключи в GitHub не публикуются.

## Первый запуск

1. Зарегистрируйте владельца через email и пароль.
2. Подтвердите email, если письмо необходимо, затем войдите.
3. На экране ожидания доступа введите одноразовый код владельца, переданный отдельно.
4. В разделе «Команда» добавьте сотрудников календаря.
5. Сотрудники самостоятельно регистрируются. Администратор одобряет их в разделе «Команда → Доступ пользователей», задаёт роль и привязку к сотруднику.

## Если письмо подтверждения ведёт не в приложение

В Supabase Dashboard → Authentication → URL Configuration добавьте этот адрес в Redirect URLs:
https://czbjcp2yqw-dot.github.io/svoyaki-control/production-planner/

Прямая страница: https://supabase.com/dashboard/project/vspytqnxxpvegwohgeag/auth/url-configuration

Не меняйте существующие адреса и настройки «Свояков». Храните код первоначального владельца отдельно от публичного репозитория.

## Ограничения

- Не проводилось тестирование входа двух реальных сотрудников в браузерах; оно потребуется перед работой с реальными съёмками.
- Для общей базы требуется интернет. Кешированная PWA-оболочка не означает возможность сохранять изменения офлайн.
- На текущем этапе общий план хранится единым JSON-документом с проверкой версий, а не отдельными SQL-строками.
- Аккредитации, умная маршрутизация, погода, ИИ-планирование и сложные графики — следующие этапы.

Клиентская библиотека Supabase зафиксирована на версии 2.119.0 (подключена через CDN).
