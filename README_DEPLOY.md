# «СВОяки — Production Control»: статическая iPhone PWA для GitHub Pages

Эта папка — **уже готовое содержимое корня репозитория**, без сборки Node.js, без Python-сервера и без Replit.

## Как опубликовать

1. Создайте пустой публичный репозиторий `svoyaki-control` в своём аккаунте GitHub.
2. Загрузите **файлы из этой папки** в корень ветки `main` (не сам ZIP).
3. В репозитории откройте `Settings → Pages → Build and deployment → Deploy from a branch`; выберите `main` и `/ (root)`; сохраните.
4. В `Settings → Pages` GitHub покажет фактический HTTPS-адрес. Для обычного проектного репозитория это формат `<логин>.github.io/svoyaki-control/` — однако фактический адрес считать подтверждённым только после успешной публикации.
5. На iPhone откройте HTTPS-адрес в **Safari** → «Поделиться» → «На экран Домой» → «Добавить». Запустите с иконки один раз с интернетом, в «Настройках» проверьте «Офлайн-пакет», затем проверьте автономную работу в авиарежиме.

## Возможности и ограничения

- Все 20 выпусков / 360 плановых этапов КПП уже загружены.
- Фактические даты, монтажный план и статус этапов редактируются; задержки учитываются в прогнозе.
- Данные хранятся в IndexedDB **на данном iPhone**, файлы приложения кэшируются Service Worker.
- Ежедневная сводка видна в разделе «Задачи». Экспорт `.ics` позволяет импортировать сроки в календарь телефона.
- **Нет общей серверной базы и автоматических push**: GitHub Pages — статический хостинг. Синхронизацию с другими телефонами и серверные уведомления нужно подключать отдельно.
- Раз в несколько дней нажимайте «Сохранить резервную копию» в настройках (JSON): iOS может удалить сохранённые данные сайта.
- Сайт GitHub Pages по умолчанию публичен; опубликованные шаблоны КПП и факты, включённые в начальный seed, будут видны посетителям. Не добавляйте в публичные файлы конфиденциальные контакты и персональные данные.
- Доступность GitHub Pages **без VPN** должна быть проверена на нужных сетях. При отсутствии сети после первого запуска кэшированная PWA продолжает работать, если iOS не удалила её данные.

По вопросам первоначального КПП используйте `data/kpp.json`; изменения происходят только в локальной БД, оригинал не перезаписывается.
